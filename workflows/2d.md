# Workflow — 2D

Owner domain: [loom-2d](../skills/loom-2d/SKILL.md).
Precondition: [foundation](foundation.md) is done.

## Before you start

- Operating tier: T0 for settings and code; T2 for the frame debugger.
- At T1 the draw-call gate falls back to a profiler capture.
- A lower tier means the visual gates fall back to a device screenshot.
- One thing must be true before phase 1: the target resolution and the
  pixels-per-unit constant are recorded in `docs/perf-targets.md`.
- The 2D package set is chosen here, not later, and never both variants.
- Every `C-xxx` id refers to [references/claims.md](../references/claims.md).
- An ADR beats any default here: see
  [docs/03-decision-records.md](../docs/03-decision-records.md).
- Repeated mistakes are listed in
  [references/anti-patterns.md](../references/anti-patterns.md).

## Phase 1 — Template, packages, pixel settings

- [ ] Create the project from the 2D template of the pinned editor version.
- [ ] Add the 2D packages: sprite, tilemap, animation, and 2D lighting.
- [ ] Point the pipeline asset at the 2D renderer variant, not the forward
      one; confirm the asset name against the pinned pipeline version.
- [ ] Set the colour space to Linear and the target resolution.
- [ ] Fix one pixels-per-unit constant and write it down.
- [ ] Add the pixel-perfect camera only when the art is pixel art (C-113).
- [ ] Decide the sprite pivot policy before the first import.
- **Gate:** a 2D test scene renders in the 2D renderer, no missing shader.

## Phase 2 — Art pipeline

- [ ] Apply the import table below with a scripted importer, not by hand.
- [ ] Reject any asset that breaks the table in the import check.
- [ ] Group sprites into one atlas per scene or per character set (C-088).
- [ ] Never mix atlas sprites and per-sprite textures for the same content.
- [ ] Keep sprites of one atlas adjacent in the sorting order.
- [ ] Turn rotation off in the atlas packing for pixel art.
- [ ] Give every atlas a name that says which scene owns it.

| Atlas rule | Value | Reason |
|---|---|---|
| Textures per atlas | stay under the platform limit | one batch per atlas |
| Texture size | 2048 by 2048 | fits the mobile texture limit |
| Padding | 2 pixels, or 4 for extruded art | stops colour bleed |
| Rotation | off for pixel art | rotation breaks the grid |
| Trim | on for HD, off for pixel art | trim shifts the pivot |
| Overlap | never across atlases | breaks the batcher |

| Import setting | Pixel art | Smooth or HD |
|---|---|---|
| Texture Type | Sprite | Sprite |
| Sprite Mode | Multiple for sheets | Single |
| Pixels Per Unit | project constant | project constant |
| Filter Mode | Point | Bilinear |
| Compression | None | Normal |
| Mip Maps | off | on for world sprites |
| Max Size | source size, no upscale | 2048 |
| Generate Physics Shape | off | off |
| Mesh Type | Tight | Tight |
| Extrude Edges | 1 to 2 pixels | off |
| Pivot | named per use | centered |
| Wrap Mode | Clamp | Clamp |
| Platform override | ASTC or ETC2 (C-043) | ASTC or ETC2 (C-043) |

```text
HUMAN HANDOFF
What:   Capture a frame debugger view of the 2D test scene
Why:    No live-editor bridge is attached, so the agent cannot capture it
Steps:  1) open the 2D test scene  2) start the frame debugger
        3) capture the frame with the sprite batcher visible
        4) report the batch count and the draw-call count
Verify: draw-call count matches the number written in docs/perf-targets.md
```

- **Gate:** the profiler shows the expected draw-call count for the scene.

## Phase 3 — Tilemap setup

- [ ] Set the grid size to the tile size in pixels.
- [ ] Author autotiling with rule tiles (C-111); keep the palette in the repo.
- [ ] Set the chunk size to the visible area plus one tile (C-089).
- [ ] Keep a separate collision tilemap and bake a composite collider (C-090).
- [ ] Leave the visual tilemap without any collider.
- [ ] Mark static tiles as static so the composite stays cheap.
- [ ] Define the sorting layers before the first level is built.
- **Gate:** the player traverses the level with stable, cheap collisions.

| Sorting layer | Holds | Order |
|---|---|---|
| Background | sky, far parallax | 0 |
| Level | tiles, walls | 10 |
| Characters | player, enemies, props | 20 |
| Effects | hit flashes, particles | 30 |
| Overlay | aim lines, markers | 40 |

## Phase 4 — Characters and physics

- [ ] Decide kinematic or dynamic per body and write the reason down.
- [ ] Give static geometry no rigidbody at all.
- [ ] Create 2D physics materials with explicit friction and bounciness.
- [ ] Put the player on its own layer and prune the collision matrix.
- [ ] Set rigidbody interpolation to Interpolate for smooth motion.
- [ ] Set gravity to zero for kinematic characters; keep the project
      gravity only where falling is part of the design.
- [ ] Use the non-alloc query forms and reuse the buffers (C-004).
- [ ] Cache every component reference in a lifecycle method (C-006).
- **Gate:** no tunnelling at top speed and no steady-state allocation.

| Body type | Use for | Body settings |
|---|---|---|
| No body | tiles, walls, background art | collider only, never a rigidbody |
| Kinematic | the player, pushed by script | gravity off, interpolation on |
| Dynamic | crates, debris, thrown items | gravity on, material friction set |
| Trigger | pickups, zones, hit boxes | no response, overlap events only |

## Phase 5 — Lighting and camera

- [ ] Add a 2D light only where it changes how the scene reads.
- [ ] Cap the overlapping light count and bake what never moves.
- [ ] Snap the pixel-perfect camera to the pixel grid; integer zoom only (C-113).
- [ ] Sort by sorting layer, not by z position.
- [ ] Parallax: one layer per depth under a single moving parent.
- [ ] Add a confiner when the play area has hard edges.
- **Gate:** the camera does not shimmer and the light count stays in budget.

| Light type | Use for | Cost |
|---|---|---|
| Global | the ambient base of the scene | one light, always on |
| Point | torches, pickups, muzzle flashes | one per source, kept few |
| Spot | a cone of focus on a hazard | one per source, kept few |
| Baked | static, authored lighting | no runtime cost |

## Phase 6 — UI and juice

- [ ] Use UI Toolkit for new screens; use uGUI for world-space HUD.
- [ ] Keep one dynamic font atlas per font and one UI sprite atlas.
- [ ] Use the set-text overloads for changing text (C-045, C-135).
- [ ] Build the juice as one toggleable group of effects.
- [ ] Pool transient effect objects instead of instantiating per hit.
- [ ] Drive the juice from events, not from polling state every frame.
- **Gate:** the UI allocates nothing per frame and the juice toggle works.

## Phase 7 — Performance and platform

- [ ] Keep one atlas per scene so the sprite batcher stays intact (C-088).
- [ ] Cut stacked transparency; overdraw dominates on mobile (C-012).
- [ ] Set the mobile texture compression override per platform (C-043).
- [ ] Set the frame cap or vSync, never both at once (C-074).
- [ ] Disable the per-camera clear and background where the design allows.
- [ ] Capture one profiler frame on the floor device.
- **Gate:** frame time and allocation are inside the budget in the capture.

| Platform | Texture format | Audio format | Notes |
|---|---|---|---|
| Android | ASTC or ETC2 | Vorbis or ADPCM | keep the size under the store limit |
| iOS | ASTC | Vorbis or ADPCM | check the memory ceiling on older devices |
| Desktop | BC | Vorbis or PCM | quality over size |
| Console | the platform format | the platform format | follow the platform checklist |

| Check | Why it hurts | Rule |
|---|---|---|
| No per-frame `GetComponent` | a hidden search every frame | cache on awake (C-006) |
| No string building per frame | garbage every frame | set-text overloads (C-045) |
| One canvas per batching group | splits the UI into batches | merge the canvases |
| No `Find*` or `Camera.main` per frame | a tagged search every frame | cache once (C-002) |
| Non-alloc physics queries | an array per call | reuse the buffers (C-004) |
| No runtime material instance | extra allocations per object | share the material (C-087) |

## Phase 8 — Verification on device

- [ ] Build for the floor device and for the widest aspect ratio.
- [ ] Check crispness while the camera moves, not only when still.
- [ ] Check collisions, UI layout, audio, and the juice toggle.
- [ ] Run the thermal soak for the length set in phase 1.
- [ ] Record the frame time, the draw calls, and the memory use.
- **Gate:** the build holds the frame rate on the floor device.

## Handoff

- 3D geometry or physics inside a 2D project → [3d](3d.md).
- Frame budget, memory, thermal work → [performance](performance.md).
- Menus, HUD, text, audio routing → [ui-audio](ui-audio.md).
- Shaders, look, quality tiers → [graphics](graphics.md).
- Build profiles, packaging, store → [release](release.md).

## Done when

- [ ] The import table holds for every sprite, checked by a scripted pass.
- [ ] The atlas plan names one atlas per scene and batching is verified.
- [ ] Tilemaps are split, colliders are composite, layers are defined.
- [ ] Movement is stable at top speed with no tunnelling.
- [ ] The camera is pixel-snapped and the art does not shimmer.
- [ ] The performance checklist passes with no per-frame allocation.
- [ ] A build on the floor device holds the target frame rate.
