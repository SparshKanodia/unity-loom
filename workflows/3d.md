# Workflow — 3D

Owner domain: [loom-3d](../skills/loom-3d/SKILL.md).
Precondition: [foundation](foundation.md) is done.
Template: [docs/07-workflow-template.md](../docs/07-workflow-template.md).

## When to use

- The project is a 3D game and the scale, layer and tag conventions are open.
- Characters need a body type and a movement model that suits the design.
- A level is being built and needs a modular kit, LOD groups and baked data.
- Content arrives from outside Unity and needs a scripted import policy.
- The scene is heavy and the draw calls, lights or shadows must come down.

## When not to use

- A 3D project that is really a 2D game, with sprite art and a tilemap ->
  [2d](2d.md), which also owns the art rules for a 3D project.
- The request is about the render pipeline, materials or the look ->
  [graphics](graphics.md).
- The request is about menus, HUD, text or sound -> [ui-audio](ui-audio.md).
- The request is that the build is slow, hot or leaks ->
  [performance](performance.md).
- The request is a headset or a handheld-AR build -> [xr](xr.md).
- The request is packaging and the store -> [release](release.md).

## Before you start

- Operating tier: T0 for code and settings; T2 for scene and profiler work.
- At T1 the bake and render gates fall back to a build and a capture.
- A lower tier means the visual gates fall back to a device screenshot.
- One thing must be true before phase 1: the units convention is written in
  `docs/perf-targets.md` and the floor device is known.
- The pipeline asset is already chosen in foundation; do not switch it here.
- Every `C-xxx` id refers to [references/claims.md](../references/claims.md).
- An ADR beats any default here: see
  [docs/03-decision-records.md](../docs/03-decision-records.md).
- Repeated mistakes are listed in
  [references/anti-patterns.md](../references/anti-patterns.md).

- `docs/perf-targets.md` belongs to the user's project, not to this
  repository. The foundation workflow creates it; if it is still missing,
  that is a phase 1 blocker rather than a broken link.

The unit convention is a project default - tune against the imported asset
sizes and the real measurements of the parts.

## Steps

### Phase 1 — Template and packages

- [ ] Create the project from the 3D template of the pinned editor version.
- [ ] Add the 3D package set: navigation, animation rigging, camera tooling.
- [ ] Point the pipeline asset at the 3D renderer variant; confirm the asset
      name against the pinned pipeline version.
- [ ] Set the colour space to Linear and the target resolution.
- [ ] Set the unit scale to 1 unit equals 1 metre.
- [ ] Keep the 2D package set out unless the project is genuinely mixed.
- **Gate:** a 3D test scene renders in the 3D renderer, no missing shader.

### Phase 2 — Scene and scale conventions

- [ ] Fix 1 unit equals 1 metre in the physics and import settings.
- [ ] Leave gravity on the engine's world axis and record its value.
- [ ] Name the layers before any prefab is authored.
- [ ] Prune the collision matrix to the pairs that actually interact.
- [ ] Reuse an existing tag before adding one; check the tag list first.
- [ ] Put the player, the enemies, and the world on separate layers.
- [ ] Keep a per-layer table in the repository next to the scene.

| Layer | Holds | Collides with |
|---|---|---|
| World | static level geometry | Player, Pickup |
| Player | the character body | World, Enemy |
| Enemy | agents and their bodies | Player, World, Enemy |
| Pickup | triggers and loose items | Player |
| Interact | interaction targets | nothing |

- **Gate:** the collision matrix has no enabled pair the design does not use.

### Phase 3 — Character

- [ ] Choose the body type per character and write the reason down.
- [ ] Use a character controller for authored feel and slopes (C-115).
- [ ] Use a rigidbody for physical interaction and stacking.
- [ ] Use a navigation agent only for creatures that pathfind.
- [ ] Give the body a capsule or box collider, never a raw mesh.
- [ ] Enable continuous detection on the fast body only.
- [ ] Let idle bodies sleep rather than simulating them (C-042).
- [ ] Add a follow camera through the camera package, not by hand.
- [ ] Cache every component reference in a lifecycle method (C-006).

| Body type | Use for | Watch for |
|---|---|---|
| Character controller | responsive platformer feel | no physical push (C-115) |
| Rigidbody | pushable, stackable objects | solver cost, tunnelling |
| Navigation agent | pathfinding creatures | bake coverage, agent radius |

- **Gate:** no tunnelling at top speed and no per-frame allocation.

### Phase 4 — Level build

- [ ] Greybox with a blockout tool, then replace it with the final kit.
- [ ] Author the level from a modular kit of prefabs, not from free edits.
- [ ] Keep a prefab per repeated structure; vary it by variant, not by fork.
- [ ] Add an LOD group to every repeated structure that is seen far away (C-091).
- [ ] Mark static geometry static, then bake the lightmap and the probes.
- [ ] Plan occlusion culling for interiors; it is baked, not live (C-116).
- [ ] Re-bake the navigation surface after the layout changes (C-092).
- [ ] Run the bake from a scripted call or the batch-mode entry point.
- **Gate:** the baked lightmap and navigation cover the playable area.

| Bake | Trigger | Verified by |
|---|---|---|
| Lightmap | static geometry marked | a probe volume with no missing data (C-107, C-108) |
| Reflection probes | every room or zone | a probe volume per zone (C-110) |
| Navigation surface | layout or agent change | an agent path across the level (C-092) |
| Occlusion culling | interior spaces | a render that culls behind walls (C-116) |

### Phase 5 — Animation and camera

- [ ] Drive the camera from the camera package with one brain per scene.
- [ ] Use timelines for scripted sequences, not for gameplay logic.
- [ ] Keep the animator parameters few and typed.
- [ ] Set the animator culling mode for offscreen characters (C-040).
- [ ] Add aim, look-at, or foot rig only where the camera shows it.
- [ ] Budget the camera shake: one source, one decay, no stacking.
- [ ] Keep gameplay logic out of animation events beyond thin triggers.
- **Gate:** camera transitions are smooth and offscreen actors are culled.

### Phase 6 — Content pipeline

- [ ] Apply the import table below with a scripted importer.
- [ ] Reject any asset that breaks the table in the import check.
- [ ] Generate LOD groups as part of import, not as a manual pass.
- [ ] Generate colliders from the source mesh only when the kit needs it.
- [ ] Use prefab variants for visual changes, not prefab copies.
- [ ] Keep one material per look so the batcher stays intact (C-010).
- [ ] Turn on GPU instancing only where the shader supports it (C-011).

Project default - tune against the device capture and the imported size.

| Import setting | Value | Why |
|---|---|---|
| Scale factor | 1 (C-119) | matches the metre convention |
| Import normals | on, read and write off | smaller memory, less CPU |
| Mesh compression | on, medium | smaller vertex buffers |
| Optimize mesh | on | drops unused attributes |
| Read and write | off | the mesh is not read at runtime |
| Generate colliders | on for the kit | a mesh collider is not valid on a moving body (C-041) |
| Generate lightmap UVs | on for baked geometry (C-107) | avoids a second UV pass |
| Convex mesh collider | off for static, on for convex moving | a non-convex mesh collider is invalid on a moving body (C-041) |
| Texture read and write | off | no runtime texture access needed |
| Texture mip maps | on | reduces shimmer and aliasing |
| Texture compression | per platform override (C-043) | the format must match the device |
| Mesh collider cooking | on, when used | faster collider creation at load |

- **Gate:** the import check reports no asset that breaks the table.

### Phase 7 — Performance and validation

- [ ] Capture a profiler frame on the floor device, not in the editor.
- [ ] Record the draw calls, the batches, the shadow casters, and the
      real-time light count.
- [ ] Cut the real-time light count and the shadow distance to the budget (C-184).
- [ ] Share materials so the batcher keeps the draw calls down (C-010).
- [ ] Check the overdraw from stacked transparency (C-012).
- [ ] Strip the shader variants the project does not use (C-014).
- [ ] Watch the thermal soak: a device that holds briefly will throttle.
- [ ] Re-measure after every change and keep the before and after numbers.

| Anti-pattern | Why it hurts | Fix | Rule |
|---|---|---|---|
| Non-convex mesh collider on a moving body | undefined behaviour | primitive or convex collider | C-041 |
| Per-frame `Find*` or `Camera.main` | a search every frame | cache once on awake | C-002, C-006 |
| Physics arrays allocated per frame | garbage every frame | non-alloc query forms | C-004, C-182 |
| Material instanced per frame | the batcher breaks | share the material | C-010 |
| `Shader.Find` in a hot path | a lookup that can fail in a build | serialized references | workflow 3d |
| Unmarked static geometry | lightmaps never bake | mark it static | workflow 3d |
| Missing LOD group | full detail drawn at any distance | generate LODs on import | workflow 3d |
| Live re-bake of navigation | a stall in play mode | bake offline, keep the surface | workflow 3d |
| Animator never culled | transform work offscreen | culling mode per rig | C-040 |
| Agents all thinking every frame | the frame budget is gone | time-slice the thinking | workflow 3d |
| No sleep on idle bodies | the solver never rests | let them sleep | C-042 |

- **Gate:** a device capture shows every metric inside the budget.

### Phase 8 — Verification

- [ ] Build for the floor device and for the widest aspect ratio.
- [ ] Play the whole playable area with the final art in place.
- [ ] Confirm that no path, trigger, or interaction was lost in the swap.
- [ ] Run the thermal soak for the length set in [foundation](foundation.md).
- [ ] Record the frame time, the draw calls, and the memory use.
- **Gate:** a release-like build holds the frame rate on the floor device.

## Limitations

- The 3D workflow does not cover 2D sprites, tilemaps or pixel art;
  [2d](2d.md) owns those.
- It does not own the render pipeline, the shaders, the post stack or the
  quality tiers; [graphics](graphics.md) owns those.
- It does not own menus, HUD, text or the audio graph;
  [ui-audio](ui-audio.md) owns those.
- The import table is a project default, not an engine requirement. A
  project with a different memory ceiling overrides it and records why.
- The level build assumes a modular kit. A hand-built one-off level has no
  LOD rule and no variant rule, so the draw-call budget has to be set by
  measurement instead.
- It does not judge level design, pacing or readability; the gate measures
  the cost of the level, never its quality.
- A bake is only valid for the layout it was made from. Any later edit
  invalidates it, and the workflow cannot detect the drift by itself.

## If a step fails

1. Stop at the failing gate; do not author further content.
2. Revert the last scene or prefab change: `git revert <sha>`, or restore the
   prefab from the last good commit.
3. Re-bake from the reverted state, and re-read the bake log to confirm the
   missing-data and coverage warnings are gone.
4. Re-read the phase gate, then re-run the import check or the device
   capture that failed.
5. If the fix needs a human with the Editor open, an artist, or a device,
   emit a `HUMAN HANDOFF` block with What, Why, Steps and Verify, and stop.
6. If the same gate fails twice, write a deviation record: the gate, the
   reason, who accepted it and the date.

## Done when

- [ ] Units, layers, tags, and the collision matrix are written down; the
      layer table sits in the repository next to the scene.
- [ ] The character body type is chosen and movement is stable at speed;
      the PlayMode test result is green.
- [ ] The level uses a modular kit with LOD groups and baked lighting; the
      bake log holds no missing-data line.
- [ ] Navigation covers the whole playable area after the final layout; an
      agent path crosses the level in the test.
- [ ] The camera is package-driven and offscreen actors are culled; the
      culling mode reads back from the rig.
- [ ] The import table holds for every model and texture; the import report
      lists no rejected asset.
- [ ] A device capture shows draw calls, lights, and frame time in budget;
      the metrics file is inside every threshold.
- [ ] A release-like build holds the target frame rate on the floor device;
      the device log shows the p95 inside the budget.
